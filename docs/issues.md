## GIF 转换相关

### [G-001] 透明背景 GIF 在微信无法播放
- **动画**: 所有透明背景 GIF
- **现象**: 在 Chrome 中正常播放，在微信中静止不动
- **原因**: 透明 GIF 使用 `disposal=2`（恢复到背景色）模式，微信 GIF 渲染器对此兼容性差
- **解决方案**: 使用白色背景（`background: #ffffff`），不使用 `omit_background`，不设 `disposal=2`
- **规则更新**: 已记录到 README 的「Export GIF」说明

### [G-002] 大尺寸 GIF (>1200px) 在微信无法播放
- **动画**: 1600x1600 和 2000x2000 版本
- **现象**: Chrome 正常，微信静止
- **原因**: 微信 GIF 渲染器对大尺寸支持有限
- **解决方案**: 保持 500x500 基础尺寸，裁剪空白区域后实际尺寸更小
- **规则更新**: 无

## 动画生成相关

### [A-001] 手臂前置时遮挡眼睛
- **动画**: clawd-clapping.svg
- **现象**: 手臂移到身前后盖住了眼睛，角色看起来"没有眼睛"
- **原因**: translate 的 y 分量为 -2px（向上移动），使手臂 y 范围变为 7-9，与眼睛 y 范围 8-10 在 y=8-9 区域重叠。加上手臂在 SVG 层级中位于眼睛之后（渲染在上层），完全遮盖了眼睛
- **解决方案**: 将 translate 的 y 分量从 -2px 改为 +1px，使手臂 y 范围变为 10-12，位于眼睛下方（眼睛底边 y=10，手臂顶边 y=10，刚好不重叠）
- **规则更新**: 需要在 reasoning-rules.md 的约束检查清单中强化——当手臂前置（translate 到躯干上方）时，必须验算 y 坐标不与眼睛(y=8~10)重叠，手臂 y 起始应 ≥10
- **根因反思**: 设计时只考虑了"手臂移到身前"的水平方向(x)，y 方向凭直觉写了 -2px（想让手抬高一点），忽略了与眼睛的空间冲突。**当部件跨区域移动时，必须逐一检查与路径上所有其他部件的碰撞关系**

### [A-002] 手臂与躯干同色导致不可辨识
- **动画**: clawd-clapping.svg
- **现象**: 手臂移到躯干前方后，因颜色完全相同(#DE886D)，无法看出手臂的位置
- **原因**: 同色部件叠加后视觉上融为一体
- **解决方案**: 在手臂方块后添加一个偏移 0.5px 的黑色半透明阴影 rect（opacity 0.25），作为手臂的投影，使手臂轮廓可辨识
- **规则更新**: 当同色部件叠加时，需要通过阴影/描边/微调色差来保证辨识度

### [A-003] 身体位移动画的语义理解——"探出去"vs"跳起来"
- **动画**: clawd-clapping.svg
- **现象**: 鼓掌时身体向左上/右上偏移，腿部静止不动
- **设计意图**: 这不是"跳起来"，而是**身体探出去**——Clawd 保持脚不动，上半身向拍手方向倾斜探出，表达投入和热情
- **关键区分**:
  - **跳跃**: 全身（含腿）translateY 向上 + 阴影缩小 + 落地压缩，参考 clawd-happy.svg
  - **探身**: 仅上半身 translate 偏移，腿部静止且加长确保不断开，阴影不变
- **规则更新**: 需要在原子动作词典中区分"跳跃"和"探身"两种不同的身体位移语义

### [A-004] 眨眼动画与表情切换动画周期冲突
- **动画**: clawd-clapping.svg
- **现象**: 普通眼不规律地随机眨眼，与鼓掌节奏不同步
- **原因**: 普通眼同时挂载了两个动画 `blink 2.5s` + `eyes-normal-vis 2.8s`，周期不同导致 scaleY 和 opacity 独立叠加，眨眼时机不可预测
- **解决方案**: 去掉独立的 blink 动画，将所有眨眼逻辑合并到 `eyes-normal-vis` 中统一控制。表情切换（普通眼↔微笑眼）时利用两组眼睛 opacity 同时为 0 的窗口作为"闭眼"过渡
- **规则更新**: 已更新 reasoning-rules.md 眼睛类原子动作——当存在表情切换时，禁止使用独立周期的 blink 动画，所有眨眼必须合并到统一的表情控制动画中

### [A-005] 跑步腿部 rotate 方案不自然
- **动画**: clawd-running.svg
- **现象**: 初版使用 crabwalk 的 rotate(-25°) + scaleY(0.7) 踮步方案，跑步看起来像蹑手蹑脚而非奔跑
- **原因**: rotate 踮步适合慢速潜行动作，跑步需要更直接的迈步感
- **解决方案**: 改为纯竖直 translateY(-1.5px) 交替，外侧组(x=3,11)和内侧组(x=5,9)反相，像素角色四腿视觉上表现为两条腿交替迈步
- **规则更新**: 已在 reasoning-rules.md 腿部类新增"迈步(跑步)"原子动作，与"踮步(潜行)"区分

### [A-006] 跑步方向感表达——手臂前置 vs 身体倾斜
- **动画**: clawd-running.svg
- **现象**: 初版用 rotate(±3°) 身体倾斜表示跑步方向，但像素风格下倾斜不自然
- **解决方案**: 取消身体倾斜(rotate 0)，改用**前置手臂**指示方向——朝前进方向的手臂 translate 到身前并全程保持，转身时交换。配合眼睛视差(±1px)和皱眉(scaleY 0.7)共同传达方向和紧迫感
- **设计原则**: 像素角色的方向感优先用**部件位置变化**（手臂前置、眼睛偏移）而非**全身旋转**来表达

### [A-007] 眼睛与身体动画时序不同步
- **动画**: clawd-running.svg
- **现象**: 眼睛看向的方向与身体移动方向不匹配——身体在左端时眼睛看中间
- **原因**: 眼睛 keyframe 的百分比节点与身体 run-move 的节点未对齐
- **解决方案**: 逐帧对比身体位置和眼睛方向，确保同一时刻眼睛看向前进方向。两端停留时睁眼(scaleY 1)，跑步中皱眉(scaleY 0.7)
- **规则更新**: 当多个动画共用同一大周期时，必须逐一验证关键帧节点对齐

### Issue A-008: SVG XML 解析错误 — CSS 注释中使用 & 符号

- **动画**: clawd-surprised.svg
- **现象**: 浏览器报 `xmlParseEntityRef: no name` 错误，SVG 完全无法渲染
- **原因**: CSS 注释中写了 `float up & fade`，`&` 在 XML 中是实体引用前缀，必须转义为 `&amp;` 或避免使用
- **解决方案**: 将注释中的 `&` 替换为 `+` 或其他安全字符
- **规则更新**: SVG 文件中（包括 CSS 注释、属性值等所有位置）禁止使用裸 `&` 字符。写注释时用 `+`、`/`、`,` 等替代

### [A-009] 身体位移导致腿与躯干分离
- **动画**: clawd-surprised.svg
- **现象**: 身体向左退后时，右侧腿留在原位，与躯干底部出现明显间隙
- **原因**: 身体 translate(-5px) + scaleX(0.85) 后右边缘移到 x≈7.2，但右腿 translate 不足（仅 -2px），腿顶部仍在 x≈9 附近，产生 ~2px 间隙
- **解决方案**:
  1. 跟随腿（左腿）：与身体同步 translate(-5px)，保持直连
  2. 支撑腿（右腿）：脚底作为 pivot（transform-origin: 10px 15px），用 rotate(-35deg) 让腿顶部向身体方向倾斜 + translate(-3.5px) 辅助位移，确保腿顶部到达身体边缘
  3. 验算公式：腿顶部 x = pivot_x + (原始x - pivot_x) * cos(θ) - (原始y - pivot_y) * sin(θ) + translateX，需 ≈ 身体边缘 x
- **核心规则**: **腿和身体不能分离**。任何身体位移动画必须同步处理腿部，方案包括：
  - 同步 translate（跟随移动）
  - pivot 在脚底 + rotate（支撑/岔开姿势）
  - 加长腿部 rect（覆盖位移间隙）
  - 以上方案可组合使用
- **规则更新**: 已更新 reasoning-rules.md——身体位移时必须验算腿部连接

### [A-010] 眼睛 scaleY 缩放因缺少 transform-box 导致位置飞离
- **动画**: clawd-note-taking.svg
- **现象**: 眼睛使用 scaleY(0.7) 做专注眯眼效果，但眼睛从 y=8 飞到 y≈5.6，完全偏离面部
- **原因**: `.eyes-focus` 未设置 `transform-box: fill-box` 和 `transform-origin: 50% 50%`，SVG 默认绕坐标系原点 (0,0) 缩放，导致 y=8 × 0.7 = 5.6
- **解决方案**: 对所有使用 scale 变换的 class 添加 `transform-box: fill-box; transform-origin: 50% 50%`
- **规则更新**: 需要在 reasoning-rules.md 约束检查清单中强化——**所有 CSS 动画类必须显式设置 transform-box 和 transform-origin**，尤其是包含 scale 变换的动画

### [A-011] 手臂同色辨识阴影的图层顺序与位置
- **动画**: clawd-note-taking.svg
- **现象**: 手臂阴影放在手臂之后（上层）导致阴影覆盖手臂表面；阴影位于顶部导致视觉不自然
- **原因**: 阴影应模拟手臂投射到下方的投影，需在手臂**下层**（先绘制），偏移到**右下方**
- **解决方案**: 阴影 rect 放在手臂 rect **之前**绘制（SVG 先绘制 = 底层），位置偏移 (+0.5px, +0.5px) 到右下方，手臂盖住大部分阴影，仅右下角露出
- **规则更新**: 手臂阴影标准做法——**先画阴影(+0.5,+0.5)，再画手臂，阴影始终在右下方底层**

### [A-012] 身前持物的视角错误——正面视图 vs 侧视图
- **动画**: clawd-note-taking.svg
- **现象**: 笔记本被画成正面展开视图（能看到整页内容和横线），但 Clawd 是正面朝向观众的，手持的笔记本应该呈现侧面视角
- **原因**: 未考虑观察者视角。Clawd 正面面对观众时，手中水平持有的物体应该呈现**顶部侧视图**——能看到翻开的页面顶部、书页厚度的侧边、封底
- **解决方案**: 笔记本改为侧视图：顶部为打开的页面（薄 rect + 文字行），中间为书页厚度（白色 rect + 横向细线表示纸边），底部为封底（深色 rect）。整体厚度控制在 1-1.5 单位
- **规则更新**: **身前持物视角规则**——当角色正面朝向观众时，手中水平持有的物体（书、平板、盘子等）应画成顶部侧视图，而非正面展开视图。竖直持有的物体（手机、牌子）则保持正面视图

### [A-013] 道具与手臂脱节——独立动画组导致不同步
- **动画**: clawd-note-taking.svg
- **现象**: 铅笔有独立的动画，与右臂的写字动画不同步，铅笔看起来飘在空中
- **原因**: 铅笔作为独立 `<g>` 放在手臂组外部，各自有独立动画
- **解决方案**: 将道具放入对应手臂的动画 `<g>` 内部，使用相对于手臂的局部坐标，道具自然跟随手臂运动。道具图层放在手臂 rect **之前**（底层），手臂盖住道具的握持区域，露出两端，形成"手握"效果
- **规则更新**: **道具挂载规则**——手持道具必须放入对应手臂的动画组内，图层在手臂之前（底层），坐标基于手臂局部空间计算

### [A-014] GIF 导出时地面阴影泄漏
- **动画**: clawd-note-taking.svg, clawd-high-jump.svg
- **现象**: 导出的 GIF 中地面阴影（黑色横条）可见，其他 GIF 都没有
- **原因**: 腿部抗锯齿边缘与地面阴影 rect 混合，产生 alpha > 128 的暗色像素，穿透 GIF 透明度阈值
- **解决方案**: 导出脚本 `tools/svg_to_gif.py` 在渲染前通过 JS 隐藏地面阴影：`document.querySelectorAll('rect[y="15"][fill="#000000"]').forEach(el => el.style.display = 'none')`。SVG 中保留完整阴影动画不受影响
- **规则更新**: 无需在 SVG 中做特殊处理，导出脚本统一处理

### [G-003] GIF 二值透明导致 opacity 渐变丢失
- **现象**: SVG 中平滑的 opacity 动画（粒子淡入淡出、阴影脉动等）在 GIF 中变成硬切的出现/消失
- **原因**: GIF 格式仅支持二值透明（1-bit alpha）。导出脚本使用 alpha ≤ 128 → 透明、> 128 → 完全不透明的阈值判定，无法表达半透明过渡
- **影响范围**: 所有使用 opacity 动画的特效（粒子、阴影、光晕等）
- **设计对策**:
  1. 特效粒子的 opacity 峰值必须 > 0.5（即 alpha > 128）才能在 GIF 中可见
  2. 父级 `<g>` 的 opacity 与动画 opacity 会相乘，设计时需计算合成值是否超过阈值
  3. 接受渐变丢失的视觉降级——SVG 中看到柔和淡入淡出，GIF 中看到硬切闪烁
  4. 若需更好的透明度表现，考虑 APNG 格式（支持完整 alpha 通道）
- **规则更新**: 设计粒子/特效时，峰值 opacity 需 > 0.5；多层 opacity 相乘后需 > 0.5

### [A-015] CSS 动画 transform 覆盖同元素的 SVG transform 属性
- **动画**: clawd-curious.svg
- **现象**: 问号通过 SVG `transform="translate(16.4, -0.9) scale(0.55)"` 定位到气泡内部，但实际渲染时问号出现在左下方远离气泡的位置
- **原因**: 同一个 `<g>` 上同时有 SVG `transform` 属性和 CSS `animation`（qmark-bounce，设置 `transform: translateY(...)`）。CSS 动画的 `transform` 会**完全覆盖** SVG 的 `transform` 属性，导致静态定位（translate + scale）被动画的 `translateY(0)` 替换，问号回到原点附近
- **解决方案**: 拆分为嵌套两层 `<g>`——外层放静态 SVG `transform`（定位和缩放），内层放 CSS 动画类。两层的 transform 独立生效，互不干扰
- **代码示例**:
  ```xml
  <!-- 错误：CSS animation 覆盖 SVG transform -->
  <g class="qmark" transform="translate(16.4, -0.9) scale(0.55)">...</g>
  
  <!-- 正确：拆成两层 -->
  <g transform="translate(16.4, -0.9) scale(0.55)">
    <g class="qmark">...</g>
  </g>
  ```
- **规则更新**: reasoning-rules.md 检查清单中已有此条（"CSS 动画与 SVG 属性冲突"），但本次仍然踩坑，说明生成时容易遗漏。需强化为：**任何带 CSS animation 的元素，禁止同时写 SVG transform 属性，必须无条件拆层**
